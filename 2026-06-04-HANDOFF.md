# UNQ Kitchen Site — Project Handoff

*2026-06-04. Read this first if you're picking up this project. It describes a finished system: one data file drives four menu pages, plus a no-code editor.*

## 1. What this is

UNQ Kitchen's website. The work consolidated several disconnected copies of the menu into **one source of truth** (`data/data.json`) that generates **four outputs**, and added a **single no-code editor** with three modes. All planned work is complete and verified.

The four outputs (all live at the repo root, URLs unchanged for stability):

| Output | File | Notes |
|---|---|---|
| Print menu (A4) | `menu/index.html` | Hand-paginated 16-page brochure |
| Digital menu | `digital-menu/index.html` | Mobile/desktop, search + category nav |
| Print package (A4) | `package/index.html` | 9 event packages + venue page |
| Digital package | `digital-package/index.html` | **New** — mobile/desktop packages |

Other site pages (not touched by this work): `index.html` (root), `homepage/`, `scanpage/`, shared `assets/` (fonts, crest).

## 2. Single source of truth — `data/data.json` (v2)

```jsonc
{
  "version": 2,
  "meta": { "currency": "₹" },
  "menu": {
    "groups":     [ {id, name} ],                    // Mains, Snacks, Live Counters
    "categories": [ {id, groupId, name, sub} ],
    "items": [
      { id, categoryId, name, desc, img,             // img is site-root-relative: "menu/assets/…"
        tags:["spicy"|"sweet"], price|null,
        showOnDigital?:false,                         // Live Counters hide from digital menu
        variants:[ {id, name, ing, price, tags} ] }
    ]
  },
  "packages": [ { id, number, name, price, description, idealLabel, idealValue,
                  waterNote, booking:{}, terms:[], cancellation:[{when,result}],
                  sections:[ {name, instruction, chip, choiceType, items:[
                      { refs:[{itemId,variantId}], displayName, note, badge } ] } ] } ],
  "venuePage": { subtitle, sections:[ {name, instruction, chip, items:[{name,note}] } ] },
  "presentation": {
    "digitalMenu":    { search, showImages, showIngredients, categoryOrder:[ids], hidden:[ids] },
    "digitalPackage": { showBooking, showTerms, showCancellation, packageOrder:[ids] },
    "printMenu": {}, "printPackage": {}
  }
}
```

- **The flat `masterMenu` is NOT stored** — it's derived at build time from `menu.items × variants`.
- Packages reference catalog items by **ID** (`itemId`/`variantId`), so renaming a dish never breaks a package. `displayName` overrides the printed label per package.
- **Print menu layout** lives separately in **`tools/print-layout.json`** (it holds verbatim HTML fragments, kept out of `data.json` to keep it clean). See §5.

## 3. The generator — `tools/build.py`

Run: `python3 tools/build.py` (from the site folder). Reads `data/data.json` (+ `tools/print-layout.json`) and writes all four outputs. Functions:

- `gen_digital_menu` — fills the digital-menu renderer with sections derived from the catalog; honors `presentation.digitalMenu` (search/images/ingredients toggles, category order/hide).
- `gen_digital_package` — renders `digital-package/index.html` from packages; honors `presentation.digitalPackage` (block toggles, order).
- `gen_print_package` — fills `tools/template-print-package.html` ({{PAGES}}/{{VENUE_PAGE}}) from packages + venue. Was verified **byte-identical** to the original.
- `gen_print_menu` — re-assembles `menu/index.html` from `tools/print-layout.json`, syncing catalog prices into each card. Supports `gen:true` blocks (catalog-built cards, via `_print_card`) for newly added/split dishes.

## 4. The editor + helper app

- **`tools/serve.py`** — tiny local server (stdlib only). `python3 tools/serve.py` (or double-click **`Start UNQ Editor.command`**). Serves `editor/index.html`, exposes `GET/POST /api/data` and `GET/POST /api/layout`; each POST backs up (`*.bak.json`) then runs `build.py`. Flags: `--port N`, `--no-open`.
- **`editor/index.html`** — single-page, vanilla JS, three modes:
  - **L1 · Catalog** — items/variants/prices/tags/images; add/delete; move category.
  - **L2 · Print** — packages (fields, sections, items via catalog picker, terms, cancellation, booking), venue page, and **Print menu layout** (move/add/remove dishes per page, reorder/delete pages, "Split shakes → per-flavour").
  - **L3 · Digital** — digital menu/package toggles, category order/hide.
  - **Save & rebuild** posts `data.json` and/or `print-layout.json` (separate dirty flags) → rebuilds everything.

> The editor MUST be opened through the server URL (the launcher does this). Opening `editor/index.html` as a file:// won't reach the API — it shows a "run the helper app" message by design.

## 5. How the print menu layout works (the subtle part)

The print menu is a hand-crafted A4 brochure (mixed `<section>`/`<div>` pages with ids + inline styles, per-dish image shapes, cover/divider pages). `tools/print-layout.json` models it as:

```jsonc
{ "head": "...", "tail": "...", "joiners": ["...between pages..."],
  "pages": [
    { "kind":"raw", "html":"<full cover/divider page>" },          // 3 of these
    { "kind":"content", "open":"<section…>", "close":"</section>",
      "blocks":[ {"t":"lit","html":"…category header/scaffolding…"},
                 {"t":"item","name":"Soup","html":"<div class=menu-item>…</div>"},
                 {"t":"item","id":"shakes","gen":true} ] }          // gen=true → built from catalog
  ] }
```

- Existing dishes are **verbatim fragments** (preserve hand-styling). Re-assembly is **byte-identical** to the original.
- `gen:true` blocks (added dishes, split shakes) are built from the catalog by `_print_card` with a **default image shape** (`shape-bowl`).
- `tools/template-print-menu.html` is the pristine reference copy of the original brochure.

## 8. Common tasks (for the next agent)

- **Change a price / dish / description:** editor L1 → Save (or edit `data/data.json` then `python3 tools/build.py`).
- **Edit a package / venue:** editor L2.
- **Toggle digital filters/search/category order:** editor L3.
- **Re-paginate the print menu / add-remove dishes / per-flavour shakes:** editor L2 → "Print menu layout" → Save → **then File → Print on `menu/index.html` to check A4**.
- **Publish:** the outputs are plain files; commit & push (GitHub Pages).

---

## 9. Verification approach (please keep this discipline)

- Print outputs were validated by **byte-diff against the originals** (print package = byte-identical; print menu = byte-identical baseline, prices sync only when a value actually changes and the card's own `₹`/`&#8377;` style is preserved).
- Data integrity was checked by **deriving the price list and diffing vs the old one** (0 unintended changes).
- Use the **sentinel-test pattern**: change one value via the API, rebuild, confirm it appears in the output, then revert.

## 10. Pending / optional / caveats

**Must do (user action):**
- Restart `Start UNQ Editor` so it serves the new `/api/layout`.
- Print-preview (File → Print) after any print-layout change — A4 overflow is not visible to the agent.

**Content gap:**
- Per-flavour shakes have **blank ingredient text** (the old digital menu grouped them). Fill in L1, or have an agent draft them.

**Optional polish (not built):**
- "Add new page" in the print-layout editor (currently rebalance across the 13 content pages).
- Image-shape picker for newly added/split print cards (default `shape-bowl`).
- A no-Python launch option, if Python on the Mac is a hassle.
- Digital package page is a functional v1; visual design could be refined.

**Gotchas:**
- Editor opens via the server URL only (not file://).
- Image paths: stored site-root-relative; digital prefixes `../`, print strips `menu/`.
- Don't normalize the print menu's mixed `₹`/`&#8377;` price styles.
- The one-off migration/reconciliation scripts were not saved — the data is already migrated, so they aren't needed.
